# KnowDB

A prototype for exploring your infrastructure in a Wikipedia-like manner,
based on the data reported from your hosts.
Click on a host to see information about it, see that port 22 is open,
read what port 22 is for, see other hosts with port 22 open, and so on.

## Running locally

The frontend is a Next.js app living at the top level of this repository,
so all `npm` and `docker` commands are run from the repository root.

With the npm dev server:

```bash
npm install && npm run dev
```

With Docker:

```bash
docker build -t knowdb . && docker run --rm -p 3000:3000 knowdb
```

Then open http://localhost:3000.

Running the Playwright tests in `tests/` (the test runner starts the dev
server for you):

```bash
npm install && npx playwright install chromium && npm test
```

Set `PORT=3100` (or any free port) if something else is already listening
on port 3000.

## How it works

The frontend reads its data at build time from the `data/` directory:

- `data/hosts.json` is a committed copy of 100 random hosts generated by
  `scripts/generate_hosts.py`, and `data/files.json` the content of the
  files found on them. The generator writes both to `tmp/`:

  ```bash
  python3 scripts/generate_hosts.py && cp tmp/hosts.json tmp/files.json data/
  node scripts/index_policy.mjs
  ```

  The second command indexes the CFEngine policy files into
  `data/policy.json` (see AGENTS.md).

  The files include a real CFEngine policy set, read from
  `tmp/proj/out/masterfiles` (a cfbs build of the Masterfiles Policy
  Framework); without it the hosts get no policy files.

- `data/info.json` is hand-written descriptions, external links and logos
  for well-known ports, software, services, users, operating systems,
  cloud providers, classes, variables, roles, filenames and IP addresses.
  Edit it to improve or extend the descriptions.
- `data/groups.json` defines groups of hosts by substring matching on OS
  and hostname.
- `data/classes.json` lists the CFEngine hard classes per operating system,
  used by the generator.
- `data/comments.json` holds example comments.

Every entry has a page with its description, external resources, similar
entries, comments and the hosts it applies to (with charts of their
operating systems and cloud providers, the host list and the ports they
listen on). The search bar at the top searches anything and accepts
filters such as `port:22 group:Windows`, `os:"Ubuntu 24"` or `disk<20%`.

## Entry types

- **Hosts**: the machines reporting in. A host page shows its OS, IP and
  MAC addresses, role and hub, disk and memory, groups, and modals listing
  its software, services, classes, variables and files. Rows in the modals
  can be pinned to show on every host page.
- **Ports**: the ports hosts listen on, with a common name such as `ssh`
  for port 22 and a description.
- **Software**: installed packages. A software page has a Versions tab, and
  each version (`apache 2.4.62`) is an entry of its own.
- **Services**: running systemd units on Linux hosts, such as `sshd` or
  `nginx`. A service can belong to a software, which links the two.
- **Local users**: accounts on the hosts, with their home directories,
  shells, groups and most recent logins across the hosts that have them.
- **Operating systems**: what the hosts run. Each has a colour that also
  colours its hosts' pixel avatars.
- **Groups**: sets of hosts defined in `data/groups.json`, such as `Linux`,
  `Windows`, `webservers` and `production`.
- **Classes**: CFEngine classes like `linux`, `ubuntu_22` or
  `policy_server`, reported by the hosts themselves.
- **Variables and values**: CFEngine `sys.*` variables and their values.
  A variable page lists its values; a value page (`sys.arch=x86_64`) lists
  its hosts.
- **Roles**: `Hub` or `Client`. A host links to its hub, and a hub links to
  a search for its clients.
- **Cloud providers**: AWS, Azure, GCP and others, or none for hosts in your
  own data center.
- **IP and MAC addresses**: an address belonging to a single host shows
  that host; well-known addresses and ranges (`127.0.0.1`, `10.0.0.0/8`)
  are described in `data/info.json`.
- **Bundles, bodies, promise types, functions, policy variables and policy
  classes**: what the CFEngine policy files define, indexed from their
  syntax trees. Each shows where in which file (with line links) it is
  defined or called, and variables, classes and function calls name the
  bundle they are in.
- **Files, paths and filenames**: the notable files on each host, such as
  the CFEngine policy, `sshd_config`, `authorized_keys` and the cf-agent
  binary. A file is identified by the SHA-256 checksum of its content and
  its page shows the full content (binaries have only a checksum and
  size), with syntax highlighting for CFEngine policy via
  [tree-sitter-cfengine](https://github.com/olehermanse/tree-sitter-cfengine). A path (`/var/cfengine/inputs/promises.cf`) lists the files found
  at it, and a filename (`promises.cf`) its paths and files.

Details of the UI, the host data format and the guidelines for generating
hosts are in [AGENTS.md](AGENTS.md).
